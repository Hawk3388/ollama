title: Speech

Speech models read text aloud. Ollama streams the audio as it is generated, so playback can start before the whole text has been spoken.

## Choose what to hear

For LFM3-Omni, choose the action explicitly:

| What you want | Command | What is spoken |
| --- | --- | --- |
| Ask a question and hear the answer | `ollama run lfm3-omni --speak --voice male-german "Warum ist der Himmel blau?"` | The model's generated answer |
| Read a text exactly as supplied | `ollama run lfm3-omni --tts --voice male-german "Der Himmel ist blau."` | Your input text |
| Generate a native audio answer | `ollama run lfm3-omni --audio "Warum ist der Himmel blau?"` | The model's native spoken answer; voice selection is unavailable |

Use `--speak` for answers with a chosen voice. The same model streams an
answer and reads complete sentences aloud. `--voice` is optional; without it the default TTS
voice is used. Use `--tts` to read the input itself, even if it is a question.
Choose only one of `--speak`, `--tts`, or `--audio`.

All three modes support `> answer.wav` to save audio. `--speak` and `--audio`
without a prompt accept independent questions at an interactive prompt;
`--tts` accepts text to read. On Windows, binary redirection requires CMD or
PowerShell 7.4+.

Existing calls remain supported: `--voice` alone reads the input, and
`--audio --voice` is an older spelling of `--speak --voice` that prints a hint
on stderr. Speech-only models such as Phonon read their input by default.

### API equivalents

| Action | API calls |
| --- | --- |
| Answer and read the reply (`--speak`) | Stream text from `/api/chat`; send complete sentences to `/v1/audio/speech` as `input` with the selected `voice` |
| Read supplied text (`--tts`) | `/v1/audio/speech` with your text as `input` |
| Native spoken answer (`--audio`) | `/api/chat` with `output_modalities: ["audio"]` |

`--speak` performs these calls for you in the CLI, submitting complete sentences
to speech while receiving the text stream. It is not a separate API
endpoint. The native audio API does not accept a selected voice.

### Read replies while they are being generated

For the same LFM3-Omni model to generate text and speech concurrently, start
the server with at least two parallel request slots:

```powershell
$env:OLLAMA_NUM_PARALLEL = "2"
.\ollama.exe serve
```

On Linux: `OLLAMA_NUM_PARALLEL=2 ./ollama serve`. Restart an existing server
after changing the setting. Additional slots require more context memory.
Then run `ollama run lfm3-omni --speak --voice male-german "Your question"`.

The first complete sentence is sent to speech immediately; playback begins
when its audio is ready. With only one slot, speech waits for text generation
to release it. The CLI continues draining text in either case, with a 1 MiB
answer limit, so a queued speech request cannot block text generation.
Cancellation or a speech failure cancels the text request too. If text
generation fails after playback has begun, partial audio may already have
been heard; the command still reports the failure.

## Setup

Start [Ollama](/quickstart) v0.40.9 or later, then download [Phonon](https://ollama.com/library/phonon):

```shell setup.sh
ollama pull phonon
```

Phonon uses Gradium's 31M English checkpoint and comes with Gradium's English voices, such as `Zoey`, `Easton`, and `Freya`. Without a voice, it speaks with the checkpoint's own voice, `default`. `ollama show phonon` lists every voice. Voice names work in any case and with or without accents.

## Speak from the terminal

`ollama run` plays the audio through your computer's speakers:

```shell examples.sh
# Speak some text
ollama run phonon "Hello from Ollama."

# Choose a voice
ollama run phonon --voice Zoey "Hi, this is Zoey."

# Speak text from another program
echo "Text from another program works too." | ollama run phonon

# Speak a chat model's answer
ollama run gemma4 --hidethinking "Tell me a fun fact about owls in two sentences." | ollama run phonon
```

Piped text is spoken as it arrives, so a chat model's answer starts playing after its first complete sentence.

Run `ollama run phonon` without any text to type lines at a `>>>` prompt. Each line is spoken when you press Enter. Press Ctrl+C to stop speaking, and type `/bye` or press Ctrl+D to exit.

Audio plays with your system's built-in player: `afplay` on macOS, the first of `paplay`, `pw-play`, `aplay`, or `ffplay` that is installed on Linux, and PowerShell on Windows.

### Save audio to a file

When the output is redirected, `ollama run` writes a WAV file instead of playing it. This also works on servers without speakers:

```shell
ollama run phonon "Save this to a file." > speech.wav
```

To hear a remote server, run `ollama` on your own computer and point it at the server. The audio plays where the command runs:

```shell
OLLAMA_HOST=my-server:11434 ollama run phonon "Hello from the server."
```

## Generate speech with the API

Use the OpenAI-compatible `/v1/audio/speech` endpoint:

<Tabs>
  <Tab title="cURL">
    ```shell
    curl http://localhost:11434/v1/audio/speech \
      -H "Content-Type: application/json" \
      -d '{
        "model": "phonon",
        "input": "Hello from Ollama.",
        "voice": "default"
      }' --output speech.wav
    ```
  </Tab>
  <Tab title="Python">
    ```python
    from openai import OpenAI

    client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

    with client.audio.speech.with_streaming_response.create(
        model="phonon",
        voice="default",
        input="Hello from Ollama.",
        response_format="wav",
    ) as response:
        response.stream_to_file("speech.wav")
    ```
  </Tab>
  <Tab title="JavaScript">
    ```javascript
    import fs from 'node:fs'
    import OpenAI from 'openai'

    const openai = new OpenAI({ baseURL: 'http://localhost:11434/v1', apiKey: 'ollama' })

    const response = await openai.audio.speech.create({
      model: 'phonon',
      voice: 'default',
      input: 'Hello from Ollama.',
      response_format: 'wav',
    })
    fs.writeFileSync('speech.wav', Buffer.from(await response.arrayBuffer()))
    ```
  </Tab>
</Tabs>

The response streams while audio is generated, so you can start playing it right away:

```shell
curl -sN http://localhost:11434/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{"model": "phonon", "input": "Playback starts while the rest is still being generated."}' \
  | ffplay -nodisp -autoexit -loglevel error -
```

### Audio formats

| `response_format` | Output |
| --- | --- |
| `wav` (default) | A WAV file: 16-bit, mono, 24 kHz. The header is written before the length is known, so its size fields hold the maximum value. |
| `pcm` | Raw 16-bit little-endian samples, mono, 24 kHz, with no header. |

### Limits

- `input` can be up to 4,096 characters per request. `ollama run` splits longer text at paragraph and sentence breaks for you.
- Prices, numbers, symbols, email addresses, and URLs are spelled out before speaking, so `$4.59` is read as "4 dollars and 59 cents". Times and numeric dates are read as written, so write dates out (`October 23`, not `10/23`) for a natural reading. Emoji, bullet characters, and markdown markers such as `*` and `#` are skipped.
- Options the model doesn't support, such as other formats, speeds, or `instructions`, return a `400` error instead of being ignored. An unknown voice returns a `400` error that lists the available voices.
- Speech models only generate speech: chat, completion, and embedding requests to them return a `400` error.

`ollama show phonon` and `/api/show` list the model's capabilities as `speech`, and its voices (`voices` in `/api/show`). See [OpenAI compatibility](/api/openai-compatibility) for every supported field.

## Native audio answers

LFM3-Omni can answer a text prompt with audio through `/api/chat`. The model
generates the answer and speech together in one native generation. This uses
the local llama.cpp GGUF runner and requires the matching audio codec projector;
`/api/show` reports the `audio_output` capability for supported models.

Use `--audio` to hear a native answer from the terminal:

```shell
ollama run lfm3-omni --audio "Why is the sky blue?"
ollama run lfm3-omni --audio "Why is the sky blue?" > answer.wav
```

Without a prompt, `ollama run lfm3-omni --audio` opens a prompt for independent
questions; it does not retain conversation history. The model's `SYSTEM` prompt
applies. Playback uses the system player in one-second pieces while generation
continues; transitions between pieces depend on the player. Redirected output is
streamed as PCM16 WAV, 24 kHz, mono. A seekable file gets its final lengths on
completion; pipes keep unknown WAV lengths. On Windows use `cmd.exe` or
PowerShell 7.4+ for binary output redirection.

This differs from piping a chat model into Phonon: `--audio` uses the Omni
model's own audio generation in one request and never calls `/v1/audio/speech`.
Models with only the `speech` capability continue to read text aloud without
`--audio`.

To hear an answer with a selected TTS voice, use `--speak`:

```shell
ollama run lfm3-omni --speak --voice male-german "Antworte kurz auf Deutsch: Warum ist der Himmel blau?"
```

This explicitly selects a text-and-TTS CLI workflow: the same model streams a
text answer and reads complete sentences through its TTS endpoint using the
chosen voice. With two server slots, speech can begin while text is still
being generated. With one slot, speech waits until text generation finishes.
Interactive input and WAV redirection work as above; generated text is not
printed to stdout. `--speak` without `--voice` uses the default TTS voice.
Use `--tts` to read the input text itself aloud.

Native audio without `--voice` still uses a single generation. The native API
continues to reject non-empty `audio.voice`: the pinned realtime backend has
no voice selector. The CLI workflow makes a text chat request followed by TTS
requests; it does not change the native audio API.

```shell
curl -N http://localhost:11434/api/chat \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "lfm3-omni",
    "runner": "llamacpp",
    "messages": [
      {"role": "system", "content": "Answer briefly in English."},
      {"role": "user", "content": "Why is the sky blue?"}
    ],
    "output_modalities": ["audio"],
    "audio": {"format": "pcm16"},
    "stream": true
  }'
```

The response is a stream of newline-delimited JSON objects. Each audio chunk
includes base64-encoded signed 16-bit little-endian PCM without a container header:

```json
{
  "model": "lfm3-omni",
  "message": {"role": "assistant", "content": ""},
  "audio": {
    "data": "AQACAA==",
    "format": "pcm16",
    "sample_rate": 24000,
    "channels": 1
  },
  "done": false
}
```

Decode `audio.data` and play the samples at 24 kHz, mono, as chunks arrive.
The final object has `done: true` and no audio field. A terminal `error` object
or a connection ending without `done: true` indicates an incomplete response.
Closing the connection cancels generation.

Native audio currently accepts one user text message and an optional preceding
system message. If no system message is provided, the model's `SYSTEM` prompt
is used. Messages are limited to 64 KiB each. Only streaming PCM16 output is
supported; chat history, media input, tools, thinking, structured output and
sampling overrides are not supported. Allowed options are `num_ctx`,
`num_batch`, `num_gpu`, `num_thread`, and `num_predict`. A nonpositive or default
`num_predict` uses a 2048-token budget shared by native text/audio decoding.
`keep_alive` controls how long the model stays loaded after the request.
